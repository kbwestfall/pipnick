Version 0.1.0dev
================

The first versioned development release of ``pipnick``, following the original
pipeline developed for an Akamai 2024 internship project.

Breaking Changes
----------------

- The command-line scripts have been reorganized.  ``pipnick_reduction`` is
  replaced by ``pipnick_metadata`` (builds the raw-data metadata table) and
  ``pipnick_reduce``.  All scripts now share the logging options ``-v
  {0,1,2}``, ``--log_file``, and ``--log_level``, which replace the previous
  ``-v``/``-vv``/``--verbosity`` options; a log file is only written when
  requested.

- The reduction and photometry pipelines no longer accept the ``--excl_files``,
  ``--excl_objs``, and ``--excl_filts`` options; frames are instead selected
  through the metadata table.

- The package logger is now ``pipnick.log`` (previously ``pipnick.logger``),
  and logging is no longer configured from JSON files.

- ``pipnick.utils.dir_nav`` is replaced by ``pipnick.metadata``, and
  ``pipnick.utils.nickel_data`` is removed; camera properties are now defined
  by the camera configuration files (see below).

- The metadata table has typed columns, a ``setup`` column, and a ``note``
  column, and science frames have the frame type ``science``.  Tables built
  by earlier versions must be rebuilt with ``pipnick_metadata``.

- ``pipnick_reduce --overwrite`` no longer rebuilds an existing metadata
  table, so that user edits to it are preserved; use ``pipnick_metadata
  --overwrite`` to rebuild it.

- ``pipnick_reduce`` requires a per-setup metadata file (``-t``), written by
  ``pipnick_metadata --split``; the ``--rawdir`` and ``--append`` options are
  removed.  Reduced science images are named
  ``<object>_C<comb_id>_<UT date>.fits`` instead of ``<raw file>_rdx.fits``.
  ``reduce_all`` takes the metadata file as its first argument and returns the
  paths to the reduced science images.

Dependency Changes
------------------

- Supports python 3.12, 3.13, and 3.14.

- Requires ``photutils>=3.0``, for ``photutils.psf.MoffatPSF`` and the
  photutils 3.x PSF-photometry interface.

- Requires ``numpy>=2.0`` and ``astropy>=7.0``.

Functionality/Performance Improvements and Additions
----------------------------------------------------

- Added support for the new Nickel Andor camera alongside the original Nickel
  camera.  Each camera is defined by a TOML configuration file in
  ``pipnick/data/cameras``, which sets how the camera is identified, which
  header keywords provide each quantity, the detector geometry, the readout
  properties, the archival bad-pixel mask, the frame-type rules, and the
  quality checks.  The camera is identified automatically from the raw file
  headers.  The Andor gain and read noise are placeholders until they are
  measured.

- ``pipnick_reduce`` combines frames in the groups set by the ``comb_id``
  column, after checking that the groups give one bias, one dark per exposure
  time, and one flat of each type per filter.  Combined darks
  (``Dark_<exptime>s.fits``) are constructed, but not yet applied.  In the
  names of the combined flats, a primed filter is written with a ``p``, e.g.,
  ``SkyFlat_ip.fits`` for ``i'``.  Science
  frames use the sky flat for their filter, or the dome flat if there is no
  sky flat.  Science frames in the same group are scaled to their median
  exposure time and combined without registration.

- The header of each reduced image lists the raw frames and calibrations used
  to construct it, and records its setup and combination group.  Rerunning
  ``pipnick_reduce`` only reprocesses images whose raw frames or calibrations
  have changed, and reports images that are no longer produced.  A reduction
  directory can only hold the images from one setup.

- ``pipnick_metadata`` identifies the instrument setup (camera, binning, read
  mode, and readout window) of each frame, checks the frame quality, and
  comments out frames that fail the checks.  ``--classify stats`` adds checks
  based on the image data.  ``--append`` adds new frames to an existing table,
  preserving user edits and commented-out rows.  A summary of each night is
  logged.

- ``pipnick_metadata --split`` writes one metadata file per instrument setup,
  named ``<base>_<xbin>x<ybin>_<readmode>_<window>``, where the window is
  ``full`` or ``win00``, ``win01``, etc. for custom readout windows.  The setup
  values and image size are stored in each file's metadata instead of as
  columns, and are restored as columns when the file is read.  Per-setup
  files can be appended to, and can be reduced directly with
  ``pipnick_reduce``.  They also have a ``comb_id`` column identifying the
  frames to combine (by default: all biases; flats by type and filter; darks
  by exposure time; everything else individually), and pointing and focus
  frames are commented out by default.

- ``pipnick_reduce`` takes the overscan and data sections, bad-pixel mask,
  saturation level, gain, and read noise from the camera configuration, for the
  binning and read mode of each frame.  For now, it reduces data from only one
  setup at a time.

- The image PSF is now modeled as a 2D Moffat function fit to a stack of bright,
  isolated sources, which is then used for the PSF photometry.

- Added ``pipnick_version``, which reports the installed version of
  ``pipnick`` and its key dependencies.

- Added package-specific exceptions in ``pipnick.pkg.exceptions``.

Under-the-hood Improvements
---------------------------

- Packaging now uses ``pyproject.toml`` only; ``setup.cfg``, ``setup.py``, and
  ``requirements.txt`` are removed.  The version is set by ``setuptools_scm``
  and written to ``pipnick/pkg/version.py``.

- Added a ``tox`` configuration and GitHub Actions continuous-integration
  tests, including a code-style check.

- Line endings are normalized to LF by ``.gitattributes``.

Documentation Updates
---------------------

- Docstrings are NumPy style and rendered by ``numpydoc``, with types
  cross-referenced to the numpy, astropy, matplotlib, photutils, and ccdproc
  documentation through ``intersphinx``.

- Added ``LICENSE.rst`` (BSD 3-Clause), ``licenses/README.rst`` describing the
  terms of adapted (PypeIt) and dependent (``loess``) third-party code, and
  ``CITATION.cff``.

Bug Fixes
---------

- ``pipnick/pipelines`` is now a proper package, so the pipelines are included
  in built wheels.

- Fixed an undefined logger in ``pipnick.utils.fits_class`` that raised a
  ``NameError`` when reading a FITS file without a mask.

- ``pipnick.utils.fits_class.Fits_Simple`` falls back to the camera bad-pixel
  mask for raw frames without a mask, instead of calling an undefined function.
