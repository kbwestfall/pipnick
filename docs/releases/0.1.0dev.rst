Version 0.1.0dev
================

The first versioned development release of ``pipnick``, following the original
pipeline developed for an Akamai 2024 internship project.

Breaking Changes
----------------

- The command-line scripts have been reorganized.  ``pipnick_reduction`` is
  replaced by ``pipnick_metadata`` (builds the raw-data metadata table) and
  ``pipnick_reduce``.  All scripts now share the logging options ``-v
  {0,1,2}``, ``--log_file``, and ``--log_level``, which replace the previous
  ``-v``/``-vv``/``--verbosity`` options; a log file is only written when
  requested.

- The reduction and photometry pipelines no longer accept the ``--excl_files``,
  ``--excl_objs``, and ``--excl_filts`` options; frames are instead selected
  through the metadata table.

- The package logger is now ``pipnick.log`` (previously ``pipnick.logger``),
  and logging is no longer configured from JSON files.

- ``pipnick.utils.dir_nav`` is replaced by ``pipnick.metadata``, and
  ``pipnick.utils.nickel_data`` is removed; camera properties are now defined
  by the camera configuration files (see below).

- The metadata table has typed columns, a ``setup`` column, and a ``note``
  column, and science frames have the frame type ``science``.  Tables built
  by earlier versions must be rebuilt with ``pipnick_metadata``.

- ``pipnick_reduce --overwrite`` no longer rebuilds an existing metadata
  table, so that user edits to it are preserved; use ``pipnick_metadata
  --overwrite`` to rebuild it.

- ``pipnick_reduce`` requires a per-setup metadata file (``-t``), written by
  ``pipnick_metadata --split``; the ``--rawdir`` and ``--append`` options are
  removed.  Reduced science images are named
  ``<object>_<filter>_C<comb_id>_<UT date>.fits`` instead of ``<raw file>_rdx.fits``.
  ``reduce_all`` takes the metadata file as its first argument and returns the
  paths to the reduced science images.

- ``pipnick_astrometry`` takes the per-setup metadata file used by
  ``pipnick_reduce`` (``-t``) and writes the astrometric solutions to the
  headers of the reduced images.  The API key is no longer a command-line
  argument; it is read from the ``ASTROMETRY_NET_API_KEY`` environment variable
  or the ``astroquery`` configuration.  The ``maindir``, ``--use_table``,
  ``--excl_files``, ``--excl_objs``, and ``--excl_filts`` options are removed.
  The script module is renamed ``pipnick.scripts.astrometry``.

- ``pipnick_photometry`` takes the per-setup metadata file used by
  ``pipnick_reduce`` (``-t``) and writes an ECSV source table for each image to
  the ``photometry`` subdirectory of the reduction directory, instead of CSV
  tables; the ``-p`` option is removed, and the detection threshold is set
  with ``--thresh`` (was ``-s``).  The script module is renamed
  ``pipnick.scripts.photometry``.

- Removed ``pipnick.pipelines.final_calib``; the photometry source tables now
  include the celestial coordinates.  Removed
  ``pipnick.metadata.default_reduced_file_name`` and the unused stamp-fitting
  functions in ``pipnick.photometry.fit`` (``fit_psf_stack``,
  ``fit_psf_single``, ``fit_psf_generic``, and ``get_graphable_pars``).

- ``pipnick.photometry.calibrate`` is rewritten: the calibration terms are
  selected by name, can be fixed, and the fit returns the covariance.
  ``photometric_calibration_coefficients``,
  ``photometric_calibration_coefficients_iterej``,
  ``calibration_design_matrix``, ``apparent_mag``, and
  ``apply_photometric_calibration`` are replaced by ``fit_calibration``,
  ``reject_outliers``, ``design_matrix``, ``zero_point``, and
  ``iterate_colors``.

Dependency Changes
------------------

- Supports python 3.12, 3.13, and 3.14.

- Requires ``photutils>=3.0``, for ``photutils.psf.MoffatPSF`` and the
  photutils 3.x PSF-photometry interface.

- Requires ``numpy>=2.0`` and ``astropy>=7.0``.

- Requires ``speclite>=0.20``, for the filter responses used to compute the
  nominal extinction.

Functionality/Performance Improvements and Additions
----------------------------------------------------

- Added support for the new Nickel Andor camera alongside the original Nickel
  camera.  Each camera is defined by a TOML configuration file in
  ``pipnick/data/cameras``, which sets how the camera is identified, which
  header keywords provide each quantity, the detector geometry, the readout
  properties, the archival bad-pixel mask, the frame-type rules, and the
  quality checks.  The camera is identified automatically from the raw file
  headers.  The gain and read noise of each readout are the nominal values:
  for the original camera, from the Lick Observatory documentation (slow
  readout only); for the Andor camera, from the performance report provided
  with the camera.

- ``pipnick_reduce`` combines frames in the groups set by the ``comb_id``
  column, after checking that the groups give one bias, one dark per exposure
  time, and one flat of each type per filter.  Combined darks
  (``Dark_<exptime>s.fits``) are constructed, but not yet applied.  In the
  names of the combined flats and science images, a primed filter is written
  with a ``p``, e.g., ``SkyFlat_ip.fits`` for ``i'``.  Science frames use the
  sky flat for their filter, or the dome flat if there is no sky flat.
  Science frames in the same group are scaled to their median exposure time
  and combined without registration.

- The header of each reduced image lists the raw frames and calibrations used
  to construct it, and records its setup and combination group.  Rerunning
  ``pipnick_reduce`` only reprocesses images whose raw frames or calibrations
  have changed, and reports images that are no longer produced.  A reduction
  directory can only hold the images from one setup.

- The metadata table, rather than the raw headers, sets the object, filter,
  exposure time, coordinates, and airmass of the reduced images, so that edits
  to the table propagate to the reduced images and their headers.  Raw header
  values that differ are kept in ``ORIG*`` keywords (e.g., ``ORIGOBJ``), and
  edited table values trigger reprocessing.  The airmass of a combined image
  is the mean of its frames.

- ``pipnick_reduce`` propagates the uncertainty of each pixel: the read noise
  (including the error in the subtracted overscan level), the Poisson noise
  of the counts, and the uncertainties of the bias and the flat.  When frames
  are combined, their uncertainties are propagated, instead of being replaced
  by the scatter of the combined values; see ``pipnick.utils.combiner``.
  Previously, the uncertainty of a single-frame science image was that of
  the calibrations only, and the uncertainty of a combined image was
  estimated from the scatter of just a few frames.

- ``pipnick_metadata`` computes the airmass of frames whose headers do not
  provide it, from the coordinates, the time of the observation, and the
  observatory location in the camera configuration, using ``astropy``.

- ``pipnick_reduce`` logs the number of saturated pixels in each frame, the
  mean overscan level, the size of the trimmed image, the number of pixels
  affected by cosmic rays, the mean level of each bias frame, and the read
  noise measured from pairs of bias frames.

- The Nickel Andor saturation level is now 65535 ADU.

- ``pipnick_astrometry`` minimizes submissions to astrometry.net.  Images are
  grouped by pointing; one image per group is solved, and the others are
  solved by matching their sources to it.  Groups without a solved image are
  solved from an overlapping solved image or by matching to the Gaia DR3
  catalog (queries are cached), and only images that cannot be solved this way
  are submitted.  Submissions send a list of locally detected sources by
  default (``--upload_image`` uploads the masked image instead), and their
  results, including failures and pending jobs, are cached so that images are
  not resubmitted after they are rewritten by ``pipnick_reduce``.  New options:
  ``--resolve``, ``--upload_image``, ``--dry_run``, ``--max_submissions``,
  ``--group_radius``, ``--min_matches``, ``--max_rms``, ``--search``,
  ``--wide_search``, ``--wide_min_matches``, ``--images``, ``--qa``,
  ``--max_sources``, ``--detect_thresh``, and ``--fwhm``.

- ``pipnick_astrometry`` logs a summary of the solution of each image, with
  the reason any image is not solved and a suggestion, and writes it to
  ``astrometry/summary.ecsv``.  It also logs the numbers of matched sources
  when a match fails, the measured telescope pointing offset, warnings for
  images with few detected sources, and (at debug level) the details of every
  match.  The documentation has a troubleshooting section.

- Images whose pointing in the metadata table is incorrect (e.g., a stale
  pointing in the raw header) are solved by matching to Gaia with a wide
  search, and the pointing error is reported.  Alternatively, the pointing
  can be corrected in the metadata table and the reduction rerun.

- The astrometry.net solutions and Gaia query results are saved exactly as
  returned, with separate indices of the submissions and queries, and are
  only modified when they are used.  Gaia is queried through the
  ``astroquery`` TAP client, so that importing ``pipnick`` does not contact
  the Gaia archive.

- All astrometric solutions are in the ICRS.  astrometry.net labels its
  solutions as FK5 (J2000), and they are relabeled as ICRS (see
  ``pipnick.astrometry.services.icrs_header``).

- Added ``pipnick.astrometry``, with source detection and matching, WCS
  fitting from matched pixel and sky coordinates (``fit_wcs``), and the
  interfaces to astrometry.net and Gaia.
  ``pipnick.pipelines.astrometry.apply_wcs`` writes a solution, e.g., one fit
  to user-provided coordinates, to a reduced image.

- ``pipnick_metadata`` identifies the instrument setup (camera, binning, read
  mode, and readout window) of each frame, checks the frame quality, and
  comments out frames that fail the checks.  ``--classify stats`` adds checks
  based on the image data.  ``--append`` adds new frames to an existing table,
  preserving user edits and commented-out rows.  A summary of each night is
  logged.

- ``pipnick_metadata --split`` writes one metadata file per instrument setup,
  named ``<base>_<xbin>x<ybin>_<readmode>_<window>``, where the window is
  ``full`` or ``win00``, ``win01``, etc. for custom readout windows.  The setup
  values and image size are stored in each file's metadata instead of as
  columns, and are restored as columns when the file is read.  Per-setup
  files can be appended to, and can be reduced directly with
  ``pipnick_reduce``.  They also have a ``comb_id`` column identifying the
  frames to combine (by default: all biases; flats by type and filter; darks
  by exposure time; everything else individually), and pointing and focus
  frames are commented out by default.

- ``pipnick_reduce`` takes the overscan and data sections, bad-pixel mask,
  saturation level, gain, and read noise from the camera configuration, for the
  binning and read mode of each frame.  For now, it reduces data from only one
  setup at a time.

- The image PSF is now modeled as a 2D Moffat function fit to a stack of bright,
  isolated sources, which is then used for the PSF photometry.

- ``pipnick_photometry`` works with ``photutils`` 3: it subtracts a 2D
  background before detecting sources, detects them with ``DAOStarFinder``,
  weights the fits by the propagated pixel errors, removes sources whose fits
  are not credible, and measures aperture fluxes with errors.  The source
  tables always provide the pixel coordinates, and provide the celestial
  coordinates if the image has an astrometric solution from
  ``pipnick_astrometry`` (masked otherwise).  They also provide instrumental
  magnitudes, and record the PSF model and the image metadata (including the
  airmass from the metadata table).  Reruns only measure images that, or
  whose settings, have changed, and only update the coordinates of images
  whose astrometric solution has changed.  A summary is written to
  ``photometry/summary.ecsv``.  New options: ``--images``, ``--qa``,
  ``--psf_thresh``, ``--fwhm``, ``--stack``, ``--min_sep``, ``--group_sep``,
  and ``--aper_radius``.

- Added ``pipnick.photometry.moffat.EllipticalMoffatPSF``, a flux-normalized
  elliptical Moffat PSF model for ``photutils``, replacing the deprecated
  ``photutils.psf.make_psf_model``.

- Added ``pipnick_version``, which reports the installed version of
  ``pipnick`` and its key dependencies.

- Added package-specific exceptions in ``pipnick.pkg.exceptions``.

- Added ``pipnick_calibrate``, which finds the Landolt standards in the
  photometry source tables by their celestial coordinates and fits the
  photometric calibration (zero point, extinction, and color terms, selected
  with ``--terms`` and optionally fixed with ``--fix``) of each band and
  night, with outlier rejection and checks of the numbers of stars and the
  airmass and color ranges.  Standards contaminated by a neighbor within their
  aperture are excluded; faint sources detected in the residuals of their PSF
  fits are not counted as neighbors.  The calibration is written to an editable TOML
  file, which is kept on rerun if edited.  The residuals of the standards,
  their leave-one-out residuals, and the drift of the zero point with time
  are reported, with optional QA figures.  ``--apply`` writes calibrated
  source tables and records the calibration in the image headers.

- If the standards of a band do not span enough airmass to measure the
  extinction, ``pipnick_calibrate`` uses the nominal extinction, and records
  this in the calibration file, the image headers, the residual table, the QA
  figures, and the summary (``--no_fallback`` disables it).

- Added the Landolt (2009, 2013) UBVRI standard-star catalog
  (``pipnick/data/catalogs/landolt.ecsv``) and ``pipnick.photometry.landolt``
  to read and match it.

- Added the Mt. Hamilton extinction curve
  (``pipnick/data/extinction/mthamextinct.dat``, from PypeIt) and
  ``pipnick.photometry.extinction``, which computes the nominal extinction of
  each band.  The camera configurations name the extinction curve of the
  observatory (``extinction`` in ``[observatory]``).

Under-the-hood Improvements
---------------------------

- The tests block internet access (``remote_data_strict``), and replace every
  method that would contact astrometry.net or the Gaia archive.

- Packaging now uses ``pyproject.toml`` only; ``setup.cfg``, ``setup.py``, and
  ``requirements.txt`` are removed.  The version is set by ``setuptools_scm``
  and written to ``pipnick/pkg/version.py``.

- Added a ``tox`` configuration and GitHub Actions continuous-integration
  tests, including a code-style check.

- Line endings are normalized to LF by ``.gitattributes``.

Documentation Updates
---------------------

- Rewrote the astrometry documentation for the new ``pipnick_astrometry``,
  including the handling of coordinate frames.

- Rewrote the photometry documentation for the new ``pipnick_photometry``.

- Added documentation for ``pipnick_calibrate``.

- Docstrings are NumPy style and rendered by ``numpydoc``, with types
  cross-referenced to the numpy, astropy, matplotlib, photutils, and ccdproc
  documentation through ``intersphinx``.

- Added ``LICENSE.rst`` (BSD 3-Clause), ``licenses/README.rst`` describing the
  terms of adapted (PypeIt) and dependent (``loess``) third-party code, and
  ``CITATION.cff``.

Bug Fixes
---------

- The PSF photometry found many duplicate detections of each star, because
  the minimum separation of detected sources was 0.1 FWHM; it is now 1 FWHM
  (``--min_sep``).

- Fixed the initial guess of ``FitEllipticalMoffat2D`` (which had too few
  parameters and used the wrong power index), the indexing of the peak in the
  initial guesses of both Moffat fitters, and
  ``EllipticalMoffat2DModel.fwhm``.

- ``pipnick/pipelines`` is now a proper package, so the pipelines are included
  in built wheels.

- Fixed an undefined logger in ``pipnick.utils.fits_class`` that raised a
  ``NameError`` when reading a FITS file without a mask.

- ``pipnick.utils.fits_class.Fits_Simple`` falls back to the camera bad-pixel
  mask for raw frames without a mask, instead of calling an undefined function.
